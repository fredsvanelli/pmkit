Plan:

1. `tracker.mjs`: a new issue's `created` and a new epic's `create` event carry milliseconds. The stamp only grows within one process: a create in the same millisecond as the last gets 1 ms more. `updated` and every other event stay in seconds. The tracker format does not change.
2. `query.mjs`: the `created` sort compares parsed instants, not strings, so `20Z` and `20.123Z` order correctly. The ID breaks a tie only for equal instants.
3. `epics.mjs` and `listDeliverables`: an epic gets `created` from its `create` event, and `sortEpics` orders by start date, then creation, then ID.
4. Tests in `query.test.mjs` and `epics.test.mjs`: same-second creates list in creation order, also when an old second-precision `created` sits next to a new one.

Issues created before the fix keep their ties: their files only hold seconds.
