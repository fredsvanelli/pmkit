## Summary

PR: https://github.com/fredsvanelli/pmkit/pull/323

The fake GitHub now has one model of Project item content, the one GitHub uses. Every item has `type` (`ISSUE`, `DRAFT_ISSUE`, `PULL_REQUEST` or `REDACTED`), and one `contentOf` answers its content for `PmkitEpicItems` and for the draft reads. PMK-88's `item.kind` is gone. `seedDraft` takes an epic Project, `seedProjectItem` takes `{ type }` for a pull request or a redacted item, and a field write on a draft item sets the value instead of failing.

Before the change, a draft in an epic Project made `PmkitEpicItems` answer `NOT_FOUND` for the id `null`, and `seedDraft` refused an epic Project. Production code needed no change: `deliverableProgress` already skips the content that is not an issue.

- Acceptance criterion 1: `scripts/fake-github-issues.mjs` (`contentOf`, `type` on every item) and `scripts/fake-github-drafts.mjs`.
- Acceptance criterion 2: `scripts/lib/github/project-ops.test.mjs` reads an epic that holds a draft issue and a pull request. `scripts/runbook-cycles-epics-github.test.mjs` runs `epic get` and `epic progress acme/12` through the CLI with the same items.
