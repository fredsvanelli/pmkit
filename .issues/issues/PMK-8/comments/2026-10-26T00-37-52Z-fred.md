## Plan

Spec: `docs/superpowers/specs/2026-10-25-pmk-8-config-schemas-design.md`
Plan: `docs/superpowers/plans/2026-10-25-pmk-8-config-schemas.md`

1. `scripts/lib/config.mjs` exports the constants the schemas mirror and splits `localConfigShapeProblems` (per-key checks) from the cross-field rules. The validators gain checks for keys the CLI reads but never checked: `labels`, `estimate.scale`, members, `defaults`, `auto_commit`, `git_host.repo`, `git_host.default_branch` and the items of `write_policy.preview`. `tracker.path` becomes optional.
2. Hand-written `schemas/pmkit.config.schema.json` and `schemas/issues.config.schema.json` (draft-07). `scripts/schemas.test.mjs` runs probe values on every key path through a small schema evaluator and through the validator, and fails when the verdicts differ. It also compares each enum and pattern with the validator's constant. The evaluator throws on a keyword it does not support.
3. `init` writes `# yaml-language-server: $schema=<url>` as the first line of both files, on a first run and with `--update`. The URL is `raw.githubusercontent.com/<owner>/<repo>/main/schemas/<file>`, built from `plugin.json`. A schema line that points somewhere else stays. `--dry-run` shows the change.
4. `commands/setup.md` and the README explain the line.

The new checks also refuse writes on a config that was already wrong, such as `auto_commit: "yes"`, which the CLI reads as off today. `init --update` then names the file to fix.

No CHANGELOG entry, since the CHANGELOG is written per release. The PR suggests the lines, including a `Setup:` line.
