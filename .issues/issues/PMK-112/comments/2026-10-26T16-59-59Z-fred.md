PMK-112 is ready for review: https://github.com/fredsvanelli/pmkit/pull/19

`pmkit validate` now lists `.pmkit/config.yaml` problems with that path, next to the `.issues/config.yaml` problems, in text and `--json`, with exit code 0. A missing config file still answers `NOT_CONFIGURED`. `init` checks the final `.pmkit/config.yaml` in both modes through `pmkitConfigRefusal`, and refuses with `INVALID_INPUT` and a next step that names the file, writing nothing, dry run included. `init --update` no longer crashes on a non-string `tracker.path`. `commands/setup.md` names the new failure.

Behavior change: a hand-written `.pmkit/config.yaml` without `version`, `git_host` or `write_policy` used to pass `init --update` and is now refused with the missing keys.

Tests: 1002 of 1002 pass. Criterion 1: "a bad .pmkit/config.yaml is reported with its path" and the CLI test "validate exits 0 and prints a .pmkit/config.yaml problem as path, code and message". Criterion 2: "init --update refuses a bad .pmkit/config.yaml and writes nothing", its `--dry-run` twin, and "pmkitConfigRefusal words the refusal for a first run and for --update". Both were also checked by hand on fixture copies, and this repo's own config still passes.
