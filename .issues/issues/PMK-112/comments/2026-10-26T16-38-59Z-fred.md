Plan: `docs/superpowers/plans/2026-10-26-pmk-112-validate-pmkit-config.md`

1. `validate`: a new `pmkitConfigProblems(root)` in `scripts/lib/validate.mjs` turns `validatePmkitConfig` output into problems at path `.pmkit/config.yaml`, code `config` (or `conflict` for merge markers), merged and sorted with the `.issues/config.yaml` problems. The exit code stays 0. A missing `.pmkit/config.yaml` still answers `NOT_CONFIGURED`, and `tracker.system: linear` alone still answers `NOT_SUPPORTED`.
2. A CLI test for the text and `--json` output of `validate`.
3. `init`: an exported `pmkitConfigRefusal(text, { update })` checks the final in-memory `.pmkit/config.yaml` in both modes before anything is built. It refuses with `INVALID_INPUT`, the problems and a next step that names the file, and writes nothing, `--dry-run` included. A minimal hand-written file (`tracker: {system: local}`) now gets refused with the missing keys, since `init --update` never filled them in.
4. `init --update` stops crashing with a `TypeError` on an empty file or a non-string `tracker.path`.
5. `commands/setup.md` "Existing config" steps 2 and 4 name `.pmkit/config.yaml` next to `.issues/config.yaml`.
