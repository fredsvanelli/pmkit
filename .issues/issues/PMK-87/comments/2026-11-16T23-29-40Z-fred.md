What was done. The GitHub tracker now implements these contract operations: `searchIssues`, `getIssue`, `createIssue`, `updateIssue`, `moveToCategory`, `assign`, `archive`, `delete`, `link`, `unlink`, `setParent`, `getHistory`, `listComments`, `comment` and `metricEvents`. Search translates the contract filter to `repository.issues` with `filterBy`, then finishes on the client. `moveToCategory` sets the Project's Status option and opens or closes the issue: `done` closes as completed, `canceled` as not planned, and every other category reopens.

These stay `NOT_SUPPORTED`, each for a reason:
- `restore`: GitHub has no trash.
- `unarchive`: unarchive is Local only (PMK-250).
- `comment` with a reply and `resolveThread`: GitHub issue comments have no threads.
- `link` of kind related on GHES: the GHES schema has no related issues.
- `delegate`, `logTime` and `listTimeEntries`: absent in the manifest.
- Cycles, epics, milestones, releases, documents, views, goals, customers and the inbox: they belong to PMK-88, PMK-89 or later issues.
