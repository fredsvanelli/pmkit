Plan for PMK-218 (spec: `docs/superpowers/specs/2026-11-09-pmk-218-improve-unblock-pr-design.md`, plan: `docs/superpowers/plans/2026-11-09-pmk-218-improve-unblock-pr.md`).

1. Rulesets: a new host read `branchRules(base)` (`gh api repos/{owner}/{repo}/rules/branches/<base>`, paged). Required approvals, required checks, strict and conversation resolution merge the classic protection and the `pull_request` / `required_status_checks` rules. With one source refused, a known unmet requirement still blocks and what is open stays `unknown`; `policies` gets `protected`, `rulesets` and `unread`. `BLOCKED` with both read names the active rule types the command does not evaluate.
2. Threads: `prThreads` pages with `endCursor` until `hasNextPage` is false, so `threads.incomplete` and the "first 100" texts go away. A next page without a cursor fails with `UPSTREAM`.
3. Blockers in `pr status` (`blockers: { blocked, blocking, pending, unknown, unchecked }` and a `blockers:` text line with the `track-agents` verdict text) and in the PR column of `/pmkit:issues:mine`.
4. One read: `getPullRequest(selector, { detail: true })` reads the pull request, its reviews and its merge state in one `gh pr view`; `prReviews` and `prMergeState` go away. The thread query stops asking for comment bodies.

Tests: host, `collectBlockers`, `pr status` CLI, and the unblock, mine, inbox-digest, investigate-bug and standup scenarios.
