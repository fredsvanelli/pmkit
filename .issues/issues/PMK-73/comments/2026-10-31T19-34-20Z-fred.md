Plan for PMK-73. Spec: docs/superpowers/specs/2026-10-31-pmk-73-security-alerts-design.md.

- Add `pmkit alerts scan [--severity ..]` (read only): runs the scanners, reads every issue and returns the alerts no issue covers, with title, type, priority and description. Data has `absent`, `incomplete`, `candidates` and `matched`.
- Key: sha256 of scanner, package and advisory URL (title when there is no URL), 12 hex digits, written as the `alert-key:` line of the description. A second run matches by that line and creates nothing.
- One issue per alert (per package). An advisory that reaches several packages opens one issue for each.
- Priority by position in the config `priorities`: critical is the first, high the second, medium the third, low the last. Short lists clamp to the last entry.
- With `incomplete` (scanner failed, unreadable issues, cut read) the command shows the warning and creates nothing. With `absent` it says the capability is absent and what is missing.
- Add `/pmkit:issues:security-alerts`, which follows todos-to-issues: dry run of each create, full preview, one question, creates in order, stop on the first failure.
- Tests, scenario, README, SKILL.md and CHANGELOG lines.
