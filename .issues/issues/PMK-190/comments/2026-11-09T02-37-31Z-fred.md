Plan for PMK-190 (spec and plan are in `docs/superpowers/specs/2026-11-08-pmk-190-customers-requests-order-design.md` and `docs/superpowers/plans/2026-11-08-pmk-190-customers-requests-order.md`).

1. Order: `sortRequests` compares the instant, not the text. `customers show` lists requests newest first (ties by id descending, no `created` last), as Linear does.
2. Manifest: `demand_signals.unsupported` adds `createRequest`, with a test.
3. `requests get` returns `problems` and prints `by` only when `triaged_by` is set.
4. `validate` reports a request that names a customer file that does not parse. `customers show <name>` says the lookup is incomplete when a customer file is unreadable. `requests list --customer` refuses an unknown customer.
5. `accept` and `decline` edit only the state lines, so `#` comments in the frontmatter stay.
6. CHANGELOG, criteria checks, `npm test` in the foreground, then the PR.
