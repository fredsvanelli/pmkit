Implementation plan (spec `docs/superpowers/specs/2026-11-10-pmk-213-improve-goals-design.md`, plan `docs/superpowers/plans/2026-11-10-pmk-213-improve-goals.md`).

1. `goal_prefix` in `.issues/config.yaml`: 2 to 5 capital letters, default `GOAL`, must differ from `id_prefix` and `epic_prefix`; schema, `validate` and every goal read use it.
2. Goal status: `proposed`, `planned`, `active`, `completed`, `canceled` (Linear's initiative statuses). A file without status reads as `active`; `goal create --status`; `goal list` and `goal get` show it. Owner stays out (the criterion reads "status or owner").
3. `goal update <id> [--title|--title-file] [--target d|none] [--status s]`, `goal close <id>` (status `completed`) and `goal delete <id>` (refuses while an epic links to the goal or an epic file does not parse). New contract operations `updateGoal` and `deleteGoal`.
4. Linear: on Business or Enterprise, `strategic_goals` becomes native for reads. `goal list`, `goal get` and `goal progress` read initiatives (epics = the initiative's projects of the team). Writes stay unsupported and are listed in the manifest. Fields taken from Linear's public schema; not run live.
5. `goal progress` returns `warnings` and `complete`: an epic file that does not parse may link to the goal, an issue file that does not parse, a cut Linear read.
6. `validate` adds `goals` to `checked`.
7. README, CHANGELOG and the initiatives-and-goals command text.
