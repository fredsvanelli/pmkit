Implementation plan (approved):

Task 1, releaseIssues takes archived and release issues gets --archived: the tracker method and the CLI flag return archived members when asked.
Task 2, choose the basis: a new pure module, scripts/lib/release-notes.mjs, picks the release, sprint or period and records why.
Task 3, group the done issues: buildNotes groups done issues by type and counts the open, canceled and chore issues it leaves out.
Task 4, the text printer: releaseNotesText in scripts/lib/format.mjs prints the basis, the skipped steps, the draft flag and the groups.
Task 5, the release-notes CLI command: a read-only command that resolves the selector, collects the issues and returns the result as text or JSON.
Task 6, /pmkit:report:release-notes: a command file that writes the notes and asks before it saves them as a document, with routing rows and scenarios.
Task 7, the term: defines Release notes in CONTEXT.md.

Acceptance criteria:
1. Groups completed issues by release, sprint or period: Tasks 3, 5 and 6.
2. Without releases it uses a sprint or a period and says so: Tasks 2, 4, 5 and 6.
3. Optionally saves the notes as a document after confirmation: Task 6.
Archived gap of release issues: Task 1.
