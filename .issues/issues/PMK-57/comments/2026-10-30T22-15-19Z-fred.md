Plan for PMK-57. Spec: `docs/superpowers/specs/2026-10-30-pmk-57-delegate-to-agent-design.md`. Plan: `docs/superpowers/plans/2026-10-30-pmk-57-delegate-to-agent.md`.

1. `scripts/lib/delegation.mjs` builds the delegation comment and reads it back. The first line is `Delegated to agent:<name> by <member>, to run locally.`, so PMK-58 can find delegations with `parseDelegation`.
2. A new contract operation, `delegate(id, agent, instructions, actor, { dryRun })`. The Local tracker assigns the issue to the `agent:` member and posts the comment with the instructions and the steps to run the agent locally. It refuses an id that is not an `agent:` member.
3. Linear answers `NOT_SUPPORTED`. Its manifest keeps `agent_delegation` absent, with `unsupported: ['delegate']` and Linear's `conditional` in `detail.workspace`.
4. The CLI gets `issues delegate <id> <agent> [--instructions-file f]`. `agent_delegation` becomes derived on Local (`source: assignee`, `run: local`), and the goldens and ADR 0001 are updated.
5. The `/pmkit:issues:delegate` command always asks before the delegation, even with `confirm: none`. After the write it asks whether to run the agent now or later. Running it means `/pmkit:issues:work` with `--as <agent>` on every write, and every question of that command stays. The README, the routing skill and the CHANGELOG get one line each.

Covers AC 1 (assigns to `agent:<name>` after confirmation) and AC 2 (comments the instructions for local execution).
