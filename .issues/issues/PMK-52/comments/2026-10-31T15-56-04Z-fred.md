Plan for PMK-52 (spec: docs/superpowers/specs/2026-10-31-pmk-52-issues-delete-design.md).

1. Local `delete`: removes `issues/<ID>/`, drops the index entry, refuses with CONFLICT when other issues hold `blockedBy`, `related`, `duplicateOf` or `parent` pointing at it. Own links, epics, sprints, releases, milestones, goals, delegations and `todo-key` do not block. They show as warnings, and mentions in other issues' text are listed. An unreadable issue file refuses, because it may hold a reference.
2. Contract: `delete` after `archive` in `TRACKER_OPERATIONS`, with a suite case for both trackers.
3. Linear: `issueDelete` (Linear's trash) with the same inbound rules read from the issue node.
4. CLI `issues delete`: full preview in text and JSON, `references` and `problems` in the JSON error body, auto_commit commits the removal.
5. `commands/issues/delete.md` (always asks, explains archive versus delete), scenario, counts, conventions, README, SKILL.md, CHANGELOG.
6. Tick the criteria, run `npm test`, open the PR.
