Plan for PMK-88 (design: docs/specs/2026-11-17-pmk-88-github-iterations-milestones-epics-design.md, plan: docs/plans/2026-11-17-pmk-88-github-iterations-milestones-epics.md, ADR 0010).

1. Select the sprint, the milestone and each item's Project in the GitHub issue fragment, and add milestone events to the timeline.
2. Grow the fake GitHub: iterations, epic Projects, status updates and milestones, including the REST milestone create.
3. Add a REST call to the GitHub client, used only to create a milestone.
4. Map the Project's iteration field as `mappings.fields.sprint` in discovery and setup.
5. Read an issue's sprint (the iteration's start date), milestone (its title) and parent (the parent issue, else the epic Project).
6. Map iterations to sprints, and build the iteration list that `openCycle` sends with every existing id.
7. Add the cycle operations: list, current, issues, open (github.com and GHE.com only), close (refused), moves and capacity in `.pmkit/capacity.yaml`, plus the sprint write and filter.
8. Add milestones: list, get, create through REST, the issue's milestone write and filter, and milestone history.
9. Add epics as linked Projects: list, get, progress, create (Project, readme and a first Inactive update with the dates) and status updates that carry the dates forward.
10. Put issues in epics through `setParent`, and filter by epic.
11. Report `cycles`, `capacity`, `deliverables` and `status_update` in the manifest, wire the tracker and run the contract suite with the new families.
12. Add the runbook `docs/runbooks/cycles-epics-github.md` and its E2E test, update the setup runbook, the README and the changelog.
13. Run `npm test` and the three GitHub runbooks.
