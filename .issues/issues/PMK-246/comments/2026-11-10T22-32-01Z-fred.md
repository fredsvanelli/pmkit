Decision PMK-246-2 (from the orchestrator): option A, the scope grows to take in the Linear release filter.

Once `listReleases` works on a workspace with releases, `release-readiness` with no flag picks a planned release as its basis, then reads its issues with `searchIssues({ release })`. Without a release filter on Linear that read refuses with NOT_SUPPORTED, while today the release read stays "not read" and readiness falls back to a milestone or a sprint. Leaving the filter out would break readiness on a Business workspace.

So PMK-246 also does these:

- The `release` filter on Linear (`searchIssues` and `issues list --release`). An issue matches when the release is any of its releases.
- `release issues` on Linear, built on that filter.
- A test each for `release-readiness --release` and `release-notes --release` on Linear.

This changes the "Out of scope" line about the `--release` filter on Linear. `release create`, `release mark-released` and `issues create --release` stay out and are follow-ups.
