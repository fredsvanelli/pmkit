## Plan

Spec: `docs/superpowers/specs/2026-10-30-pmk-45-strategic-goals-design.md`. Plan: `docs/superpowers/plans/2026-10-30-pmk-45-strategic-goals.md`.

1. **Goal file.** `.issues/goals/<ID>.md` with `title`, an optional `target` and the description as the body. The ID is `GOAL-` plus a code that follows `id_style` (`GOAL-7K3Q` or `GOAL-1`). The prefix is fixed, and a `goal_prefix` key is a follow-up. (criterion 1)
2. **Epic link.** An optional `goal` key in `epic.md`. `epic create --goal <id>` sets it on a new epic, and `epic goal <epic> <goal|none>` sets or removes it on an existing one and logs an `update` event. A goal's epic list is computed on read. The tracker format stays 2, so no migration is needed. (criterion 1)
3. **Operations and CLI.** `listGoals`, `getGoal`, `createGoal`, `goalProgress` and `setEpicGoal` in the contract. The commands are `goal list`, `goal get`, `goal create` and `goal progress`. `goalProgress` returns each epic's `deliverableProgress` and the sums, from one shared function, so the counting rule stays in one place. The `--json` output is stable for PMK-67. (criterion 2)
4. **Capability.** `SERVED_BY.strategic_goals` lists the five commands, so Local reports `native`. Linear on a Business plan reports `absent` with `detail.workspace: native` and the five operations under `unsupported`. The Linear commands answer `NOT_SUPPORTED`. ADR-0001's counts change to 17 served and 13 native. (criterion 3)
5. **Validate, doctor and export.** `validate` reports `goal` problems and missing `goal` references from epics. The doctor lists the `goal` code. `local-migrate export` lists goals among the losses.
6. **Docs.** README CLI table, CHANGELOG, a Goal entry in `CONTEXT.md`, the design spec and ADR-0001.
