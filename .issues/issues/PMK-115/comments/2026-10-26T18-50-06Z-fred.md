Plan: `docs/superpowers/plans/2026-10-26-pmk-115-contract-sprint-aliases.md`

Tests only. Five new `it` blocks in `scripts/contract-suite.mjs`, after the cycle test, so every adapter runs them. `scripts/contract.test.mjs` runs the suite in three local setups.

The suite uses the contract's forms: `sprint: 'current'` in writes and in the search filter, `null` to take an issue out of its sprint in `updateIssue` and `moveToCycle`, and `sprint: 'none'` in the search filter. It does not assert what the string `'none'` does in a write.

1. Tests 1 and 2: with an active sprint, `createIssue`, `updateIssue` and `moveToCycle` with `current` store the active sprint id, and `null` takes the issue out.
2. Test 3, with a snapshot helper: with no active sprint (a fresh tracker, a planned sprint only, a closed sprint), the three writes with `current` fail with `INVALID_INPUT`, and the issue, its history, the sprints and the metric events stay the same.
3. Tests 4 and 5: `searchIssues` with `current` and `none`, with and without an active sprint. With none active, `current` returns an empty `issues` list. The test reads `.issues` only, which leaves room for PMK-116.

The product code already behaves this way, so the failing step of each task is a mutation of `scripts/lib/local/tracker.mjs` that the new tests catch, undone with `git checkout`. `contract.test.mjs` goes from 59 to 74 tests.
