## Summary

PR #327 (https://github.com/fredsvanelli/pmkit/pull/327) adds the `PMKIT_LIVE` checks of the GitHub adapter and fixes four GraphQL documents that GitHub's published schemas refuse.

**The live checks are built and verified against the fake GitHub, but nobody has run them against github.com or GHES yet**, by the user's decision. `docs/runbooks/live-checks-github.md` says how to run them.

- `scripts/lib/github/client-live.mjs` holds eight checks, one group per criterion: the client's error shapes on github.com (criterion 1), `discover` on a repository with a Project (2), `openCycle` keeping item iterations on a throwaway Project (3), and a draft conversion on GHES, skipped with a note when no GHES host is set (4).
- Schema fixes: `PmkitDraftProject` reads through `ProjectV2Owner`; the issue fragment aliases the number and date issue field values; the Project read leaves out `isIssueField` and multi-select fields on GHES, in discovery and in `init`; GHES issue fields start at 3.22 (ADR 0007 amended). After the fixes, 68 documents validate against the fpt and GHES 3.19 to 3.22 schemas with 0 failures.
- Tests: `npm test` 6312 tests, 0 failures, 105 skipped (contract-suite family skips, as on develop). All six GitHub runbook tests pass.
- Docs: design `docs/specs/2026-11-18-pmk-335-github-live-checks-design.md`, plan `docs/plans/2026-11-18-pmk-335-github-live-checks.md`, new runbook `live-checks-github.md`, a GHES step in `setup-github.md`, CHANGELOG and README.

Open minor finding (review-work 9.9): `client-live.mjs` has no SIGINT handler, so a run killed with Ctrl-C leaves its drafts (and an added iteration) on the throwaway Project; the runbook's "Clean up after a stopped run" covers it.

Follow-up candidates: a SIGINT handler for the writing checks; Status change events from GHES 3.20, whose schema already has them; running the live checks and recording the result.
