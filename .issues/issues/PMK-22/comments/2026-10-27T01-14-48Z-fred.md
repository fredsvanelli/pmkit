Implementation plan (approved):
Task 1. Release file module. Adds `scripts/lib/local/releases.mjs` for the id and tag rules, parsing, serializing and version order, plus the release typedefs.
Task 2. List, get and create releases in the tracker. Adds the release operations to `tracker.mjs`, the contract and the contract suite, with a new test file.
Task 3. The issue's `release` field. Adds `release` to issue create, update and normalize, and to the issue record format.
Task 4. The issues of a release, and marking it released. Adds the release-issues query and the mark-released operation to the tracker and the contract.
Task 5. `validate` checks release files and references, and doctor fixes them. Adds the release checks to `validate.mjs` and `commands/local/doctor.md`.
Task 6. The `release` commands and `--release` on issues. Adds the `release` command group, `--release` on `issues create` and `issues update`, and a git tag check in `pmkit.mjs`.
Task 7. `capabilities` reports `releases` as native. Changes `capabilities.mjs` and ADR-0001.
Task 8. Docs and command files. Updates the design spec, `CONTEXT.md`, `README.md`, and the issue create, update and groom command files.
Criterion 1. `releases/<version>.md` holds a release, optionally tied to a git tag. Covered by Tasks 1, 2, 5 and 8.
Criterion 2. The CLI lists releases, lists the issues of a release and marks a release released. Covered by Tasks 2, 3, 4 and 6.
Criterion 3. `capabilities` reports `releases` as native. Covered by Task 7.
Plan: `docs/superpowers/plans/2026-10-26-pmk-22-local-releases.md` on branch `pmk-22-add-releases-to-the-local-tracker`.
