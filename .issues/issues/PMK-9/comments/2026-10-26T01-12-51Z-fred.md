## Plan

Spec: `docs/superpowers/specs/2026-10-25-pmk-9-golden-outputs-design.md`
Plan: `docs/superpowers/plans/2026-10-25-pmk-9-golden-outputs.md`

1. Two new fixtures in `scripts/__fixtures__/`. `messy-merge` has numbered IDs, an add/add conflict, conflict markers on a status line, `events.jsonl` lines out of order and two active sprints. `no-sprints` is a team tracker with no sprint files. `basic` is the empty repository and `team` is the small team, both unchanged, since other tests depend on them.
2. `scripts/goldens.test.mjs` runs every command in the `COMMANDS` table on `basic`, `team`, `messy-merge` and `no-sprints`, in text and `--json`. Each write also runs with `--dry-run`, and every run uses a fresh copy. Each golden file at `scripts/__goldens__/<fixture>/<command>.txt` records the exit code, stdout and stderr. The test fails on a difference with a line diff, and it also fails when a command has no case.
3. `PMKIT_NOW`, `PMKIT_SEED`, `TZ=UTC` and an empty git config make the output deterministic. Temporary paths become `<root>`. `UPDATE_GOLDENS=1` regenerates the goldens and deletes stale ones. The runs go through a small pool to keep `npm test` fast.

Every open EPC-1 PR changes some command output, so the goldens need a regeneration after those merges. No CHANGELOG entry, since the CHANGELOG is written per release.
