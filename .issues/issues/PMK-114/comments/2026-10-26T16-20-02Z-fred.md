## Plan

Spec: `docs/superpowers/specs/2026-10-26-pmk-114-sprint-current-design.md`
Plan: `docs/superpowers/plans/2026-10-26-pmk-114-sprint-current.md`

The cause: `requireSprint` in `scripts/lib/local/tracker.mjs` treats `current` as a sprint id. `issues list` and `cycle add` resolve `current` elsewhere in the same file.

1. Tracker: a new `requireActiveSprintId()` next to `activeSprintId`. `requireSprint` calls it for `current`, and `moveToCycle` uses it too, so create, update and `cycle add` give the same error with no active sprint: `INVALID_INPUT`, "there is no active sprint", next step `pmkit cycle list`. The stored and logged value is the resolved sprint id, and `--dry-run` resolves it too.
2. CLI tests for create and update, with and without an active sprint, plus `none` and the existing `cycle add` error. The usage strings become `[--sprint id|current|none]`.
3. Command texts: `commands/issues/create.md` says `INVALID_INPUT` (not `NOT_FOUND`) for a missing parent, sprint or member, which is what the CLI already answers. `create.md` and `update.md` say the dry run fails with no active sprint and offer `/pmkit:cycle:plan` or going on without a sprint.

No CHANGELOG entry, since the CHANGELOG is written per release.
