Plan for PMK-225. Spec: `docs/superpowers/specs/2026-11-09-pmk-225-improve-user-inbox-design.md`. Plan: `docs/superpowers/plans/2026-11-09-pmk-225-improve-user-inbox.md`.

1. User store: the inbox file is keyed by the git remote (host/owner/name, so https and ssh share it), falling back to the checkout path; the old path file is read until the first write. Every write takes `<file>.lock` (10 s wait, stale after 30 s, `CONFLICT` on timeout) and merges with the entry on disk.
2. Local: a new `status` kind for moves of an issue assigned to the member, by someone else (`from`, `to`, `counts.statusChanges`). An entry that has not covered a kind yet gets the 14-day first-list cut for that kind, so old status changes do not flood. Mark-read merges under the lock, so two at once keep both keys.
3. Linear: `listNotifications` and `markRead` read `Notification` objects (assignment, mention, comment mention, status change) and write `notificationUpdate(readAt)`. `user_inbox` becomes native on Linear. Only the key owner's inbox; a cut read is incomplete and blocks mark-read; a failed write in the middle stops and names what was marked and what is left.
4. CLI: `inbox list --reviews [--login l ...]` adds the review requests from one `gh pr list` call, "not verified" (never 0) when GitHub cannot be read. The text table gains Text and Seen columns.
5. CHANGELOG, SKILL.md, README, inbox-digest wording.
