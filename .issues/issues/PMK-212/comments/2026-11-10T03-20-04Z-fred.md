Implementation plan (spec: `docs/superpowers/specs/2026-11-10-pmk-212-improve-saved-views-design.md`, plan: `docs/superpowers/plans/2026-11-10-pmk-212-improve-saved-views.md`).

1. `views delete <name>` and `views rename <name> <new-name>` on Local: new contract operations `deleteView` and `renameView`. Delete removes `.issues/views/<name>.yaml` (a broken file too, and says what was lost). Rename moves the file as is, refuses a name another view has in any case, and allows a case-only rename. Both take `--dry-run`. `SERVED_BY.saved_views` names them.
2. `validate`: `checked.views` counts the view files, `filter: {}` is a problem, and two view files whose names differ only in case are a problem.
3. `views run <name> [--limit n] [--sort s]` overrides the stored limit and order for one run. The overrides are checked first, so a bad `--sort` is never reported as `view_out_of_date`. The JSON adds `overrides`.
4. Linear: `views list` and `views run` read the workspace's custom views (`customViews`, `customView.issues`) of the scope team plus the team-less ones. A cut read is reported as incomplete. Duplicate names answer `ambiguous_view_name` with the ids, and a view runs by id too. `saveView`, `deleteView` and `renameView` answer `NOT_SUPPORTED` (views are written in Linear), and `saved_views` becomes `native` with those three in `detail.unsupported`.
5. Docs: `run-view.md`, `find.md`, `doctor.md`, README, CHANGELOG.

Builder's call: Linear views are read and run only; writing them from pmkit is a follow-up candidate.
