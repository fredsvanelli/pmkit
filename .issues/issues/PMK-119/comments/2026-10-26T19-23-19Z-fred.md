## Plan

Spec: `docs/superpowers/specs/2026-10-26-pmk-119-validate-unsupported-tracker-design.md`
Plan: `docs/superpowers/plans/2026-10-26-pmk-119-validate-unsupported-tracker.md`

Today `validate` exits 2 with `NOT_SUPPORTED` when `tracker.system` is `linear` and nothing else is wrong. With another bad key it lists only that key and leaves the tracker out.

1. `scripts/lib/config.mjs` exports `unsupportedTracker(system)`, the "only `local` is supported" rule with its message and next step. `loadConfig` uses it, so every other command still fails with the same `NOT_SUPPORTED` error.
2. `pmkitConfigProblems` in `scripts/lib/validate.mjs` adds `{ path: '.pmkit/config.yaml', code: 'config', message: 'tracker.system "linear" is not supported yet, set it to local' }` for a known tracker other than `local`. It first checks that the file and `tracker` are maps, so an empty file or `tracker: linear` as a string gives today's problems and no crash. `validate` then exits 0 with `checked` at zero, as it does for the other early returns.

This reverses PMK-112's choice to keep the throw for `linear` alone. The support policy does not change: `loadConfig` and every other command still reject the tracker. Setup step 2 now shows the problem instead of stopping on the error.

Two tasks, tests first. No golden should change.
