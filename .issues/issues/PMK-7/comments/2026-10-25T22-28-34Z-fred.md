## Plan

Spec: `docs/superpowers/specs/2026-10-25-pmk-7-query-index-design.md`
Plan: `docs/superpowers/plans/2026-10-25-pmk-7-query-index.md`

1. Add `scripts/lib/local/query-index.mjs`. The index lives in `.issues/.cache/index.json` (with its own `.gitignore`). Each entry pairs the parsed issue with the file's size, mtime, ctime and inode, taken before the read. An entry changed within 2 s of the index write is reparsed, as git does.
2. `readAll()` and every search read through the index and rebuild only the entries whose files changed. Any index failure falls back to the plain scan without a warning. Dry runs and older tracker formats never write the cache, and CLI writes never touch it.
3. An equivalence suite compares the indexed and plain results over every fixture, many `issues list` filters and states such as hand edits, deleted folders, new folders and corrupt indexes.
4. Add `pmkit reindex`, which rebuilds the index and reports how many issues it read.
5. `/pmkit:local:doctor` runs `reindex` as its last step. Update README, CONTEXT.md and ADR-0001.

The tracker format, the capability manifest and the contract do not change.
