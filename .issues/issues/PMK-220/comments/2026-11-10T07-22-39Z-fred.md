Plan (PMK-220), from `docs/superpowers/plans/2026-11-10-pmk-220-improve-team-load.md`:

1. `defaults.overload_factor` (number of 1 or more, default 1.5) in `.issues/config.yaml`, schema and template; `teamLoad` and `proposeMoves` use it, the report carries `overloadFactor`.
2. Delivered column: issues done in the sprint per member, one extra read; not verified (`null`, `?`) when the read is cut or a file does not parse; no column without a sprint.
3. Blocked issues: a `Blocked` count per member; blockers outside the scope read once; an unreadable blocker counts as blocking with a warning; the proposal never moves a blocked issue in `todo` (new no-move reason `blocked`), except away from a member with availability 0.
4. Read once: split `teamLoadReport` into `readLoadInputs` and `buildLoadReport`; `discover()` and the manifest read once; `team capacity` builds the before and after load from one read.
5. Command file, goldens, scenario, CHANGELOG and README follow.
