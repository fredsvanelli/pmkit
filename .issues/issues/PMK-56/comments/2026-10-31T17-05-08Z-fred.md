# PMK-56 issues bulk Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `issues bulk <change> <value>` and `/pmkit:issues:bulk`, which apply one change to every issue a filter returns after a full preview frozen by a digest.

**Architecture:** A pure library `scripts/lib/bulk.mjs` builds the change, the per-issue preview and the digest. The CLI command reads the filter (flags or a saved view), dry-runs the existing contract operation for each issue, and writes with the same operations only when `--expect` matches the digest.

**Tech Stack:** Node ESM, `node:test`, the existing tracker contract.

**Spec:** `docs/superpowers/specs/2026-10-31-pmk-56-bulk-operation-design.md`

## Global Constraints

- No new write path: writes go through `moveToCategory`, `assign`, `updateIssue`, `moveToCycle`, `setParent`, `link`, `unlink`.
- Batch cap 50 by default, `--max` up to 200.
- Digest format `sha256:<64 hex>`, real run needs `--expect <digest>`, mismatch is `CONFLICT`.
- Commit trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; every commit has `(PMK-56)`.
- Keep edits to `README.md`, `CHANGELOG.md`, `skills/pmkit/`, `scripts/lib/args.mjs`, `scripts/pmkit.mjs` small. Do not touch the Local store.

## Review Focus

- Issue changes between preview and write: `--expect` mismatch writes nothing.
- Filter now returns another issue: same digest mismatch.
- Unreadable issue file (`problems`): preview shows it, real run refuses.
- `hasMore` on Linear: refuses to write.
- More matches than the cap: refused with the count.
- A write fails midway: stops, lists applied, failed and remaining, never retries.
- No filter flag: refused. `--archived`, `--limit`, `--sort` not accepted.
- Linear `milestone` and `release`: `NOT_SUPPORTED`.

### Task 1: Pure library

**Files:** Create `scripts/lib/bulk.mjs`, `scripts/bulk.test.mjs`.

**Interfaces:**
- Produces `parseChange(kind, value, { flags, scale }) -> { kind, value, text, apply(tracker, issue, actor, { dryRun }) -> Promise<{ before, after }> }`, throwing `INVALID_INPUT` for an unknown kind, a bad value or a missing `--kind` on `link`.
- Produces `fieldChanges(before, after) -> [{ field, from, to }]` (ignores `updated`).
- Produces `buildPreview({ change, issues, results, problems, hasMore, max }) -> { items, writes, blockers, digest }`.
- Produces `bulkText(preview, { dryRun })`.
- Produces `CHANGES` (the list of kinds).
