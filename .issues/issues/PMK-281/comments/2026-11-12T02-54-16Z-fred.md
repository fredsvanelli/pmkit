Plan for PMK-281 (spec and plan in docs/superpowers/, branch pmk-281-match-commonmark-on-which-lines):

1. INTERRUPTS_PARAGRAPH narrows: an ordered item interrupts only when it starts at 1, and an empty item (`-`, `*`, `1.`) never does. A wide BLOCK_START test keeps `Accepted\n\n2. foo\n===` and `Accepted\n\n-\n===` open, since after a blank line they start a list. Covers criterion 1.
2. A tab-aware indentColumns replaces NOT_PARAGRAPH_START. An indented line that starts a block is code: skip the code run, and the paragraph starts at the first less indented line (`Accepted\n\n\tcode\nmore\n===` ends at `more`). Inside a paragraph a tab line is a continuation. Covers criterion 2.
3. From the PMK-280 review: LIST_ITEM no longer matches a thematic break (`- - -`), and its comment moves to the right constant.
4. Tests in scripts/adr.test.mjs (adrInfo, setAdrStatus, docs adr-get, docs adr-status), a CHANGELOG line, npm test.

Out of scope: PMK-282, PMK-283, tables and HTML blocks.
