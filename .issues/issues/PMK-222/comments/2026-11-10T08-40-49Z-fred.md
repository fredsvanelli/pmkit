Plan (spec: docs/superpowers/specs/2026-11-10-pmk-222-improve-issues-delete-design.md, plan: docs/superpowers/plans/2026-11-10-pmk-222-improve-issues-delete.md)

1. Criterion 1: `issues delete` runs `git grep` from the repository root (`.issues/` excluded), keeps the lines the existing mention rule accepts, and returns `files: [{ path, lines }]`. A failed scan stays in `unchecked` with its reason. On Linear, `unchecked` also names Linear documents.
2. Criterion 2: new `issues restore <id>` (tracker method `restore`). On Linear it sends `issueUnarchive` for an issue in the trash. On Local it answers NOT_SUPPORTED, with the git commands that bring the folder back as the next step.
3. Criterion 3: `issues link <from> <to...> --remove` takes several targets. One target keeps today's JSON. A failure partway stops and reports applied, failed and remaining, as `issues bulk` does. The delete refusal then groups the blockedBy and related next steps into one command each.
4. Criterion 4: the contract delete test (issues family) already runs live, and the live allowlist gains `issueUnarchive` so the restore runs live too. The run needs LINEAR_API_KEY and PMKIT_LIVE_WORKSPACE, which this worktree does not have, so this criterion stays open until someone with the key runs it.
5. Criterion 5: tests for `../` IDs, an epic ID, and `issueDelete` answering `success: false`.
