# PMK-252 Map issue docs on Linear Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline) with superpowers:test-driven-development.

**Goal:** `docs` of an issue is read and written on Linear as attachments, and record-decision links the ADR there.

**Architecture:** attachments are read like PMK-246 releases (batched query per 100 issues, per-issue fallback, unread means unknown); writes diff the whole new list into `attachmentCreate` and `attachmentDelete`.

**Tech Stack:** Node ESM, `node:test`, the fake Linear API in `scripts/fake-linear-api.mjs`.

**Spec:** `docs/superpowers/specs/2026-11-10-pmk-252-linear-issue-docs-design.md`

## Global Constraints

- Linear refuses a query above 10000 complexity points: the issue fragment does not grow; the batch page is 20 attachments per issue, 100 issues per request; a test pins the sizes.
- No read per issue in list, search or views.
- A refused or failed read is `docsUnknown` plus a `note:`, never an empty list.
- Every commit message carries `(PMK-252)` and ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

- Attachment read fails (query too complex): issue shows `docsUnknown`, a note, no `docs` key; a docs write refuses and sends no mutation.
- An issue with other attachments (PR links, no `pmkitDoc`): they are not docs.
- An issue with more than 20 attachments: every page is read.
- No `git_host.repo`: `--add-doc` refused with `NOT_CONFIGURED` and no request; read works.
- A mutation fails in the middle: the error lists what was added or removed and what was not.
