## Plan

Spec: `docs/superpowers/specs/2026-10-25-pmk-6-auto-commit-design.md`
Plan: `docs/superpowers/plans/2026-10-25-pmk-6-auto-commit.md`

The CLI already reads `auto_commit`, but its commit runs `git add -- .issues`, so it sweeps any other tracker change into the commit.

1. The Local tracker records every file it writes (`writtenFiles()`), and the auto-commit adds and commits only those paths with `--literal-pathspecs`. Staged work elsewhere stays staged. A write that changes nothing makes no commit. `migrate` keeps committing the tracker folder.
2. Table-driven tests pin all three criteria for every write command: one commit per write with `auto_commit: true`, no commit with `false` or without the key, and no commit with `--dry-run`.
3. Describe `auto_commit` in the config template and the README.
