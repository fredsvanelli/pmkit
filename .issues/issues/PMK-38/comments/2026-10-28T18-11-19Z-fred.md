# PMK-38 Linear projects as epics implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development or superpowers:executing-plans, as the user picks, to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Linear tracker answer the Deliverables, Milestones (read) and Documents (read) families, so projects are epics with progress and health, a status update creates a project update, and project milestones and documents are readable. An issue joins an epic through `parent`.

**Architecture:** `projects.mjs` is pure: the GraphQL text and the mappers `epicKey`, `toEpic`, `toStatusUpdate`, `toMilestone`, `toDocument`. `project-ops.mjs` holds the operations that send requests, and `tracker.mjs` merges them behind `guarded`. The issue code learns the project through two small hooks: `ISSUE_FRAGMENT` gains `project` and `projectMilestone`, and `issue-ops`/`relation-ops` receive a `resolveEpic` function from the project operations. A stateful fake (`fakeLinearProjects`) answers the project documents by operation name, so the contract suite runs the `deliverables` family in `npm test`.

**Tech stack:** Node.js ESM, `node:test`, `node:crypto` `randomUUID`, the PMK-30 client (`request`, `paginate`, `session`), `fakeLinearFetch` and `fakeLinearIssues` from `scripts/fake-linear-api.mjs`.

**Spec:** `docs/superpowers/specs/2026-10-28-pmk-38-linear-projects-as-epics-design.md`

## Global constraints

- `npm test` opens no socket. Every Linear test injects `fakeLinearFetch`, and every test that reaches the user store sets `PMKIT_HOME` through `userStoreEnv()`.
- `package.json` gains no dependency (ADR-0003). No config schema changes.
- Every Local tracker output stays byte-identical. The goldens and the three Local contract runs still run every test.
- The key never appears in output, an error, a cache file or a command line. Tests use `FAKE_KEY`.
- No file, commit or comment holds the real workspace URL key, the real team key or a real project name. Examples use `acme` and `ACME`. Docs say "the sandbox workspace". Task 16 runs the private-name check.
- No task writes to Linear. The live check (Task 15) is read-only, runs behind `PMKIT_LIVE=1`, and its fetch wrapper refuses any document that starts with `mutation`. Write it with the workspace as `$PMKIT_LIVE_WORKSPACE`, never a value.
- The adapter never sends one mutation twice. A write uses a client-chosen id.
- Answered questions bind the code: milestones and documents are read only (`createMilestone` and `createDocument` answer `NOT_SUPPORTED`, and the manifest `detail` says so); `setParent(id, null)` clears the parent issue and the project; a paused project maps to `backlog`; `epic list` covers the configured team only.
- PMK-36 (history, comments) merges first and PMK-37 (cycles) edits the same files. Edits to shared files stay small and grouped: one added line or one block per file, no reformatting, no reordering. These shared files are `documents.mjs` (`ISSUE_FRAGMENT`), `tracker.mjs`, `scripts/fake-linear-api.mjs` (`toNode`, `applyFields`, `comparators`) and `scripts/contract-suite.mjs`. A new fake store and new modules carry the rest.
- Every commit message carries `(PMK-38)` and ends with exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Code, comments and messages follow `~/.claude/skills/unslop/SKILL.md`.
- Run one test file with `node --test <file>`. Run everything with `npm test`.

## Review focus

1. An issue with a parent issue and a project. `parent` must read as the parent issue, and clearing it must clear both. Tasks 5 and 7 test it.
2. The three project keys. The identifier, the slug and the UUID must each find the project and answer the canonical id. Tasks 1 and 9 test it.
3. A workspace where `identifier` is null. The slug in lower case becomes the id. Tasks 1, 4 and 9 test it.
4. `searchIssues --parent <epic>` must return only issues whose shown parent is the epic. Task 8 tests it.
5. A merge with PMK-36 and PMK-37. Task 3 and Task 13 keep their edits to one block each.
