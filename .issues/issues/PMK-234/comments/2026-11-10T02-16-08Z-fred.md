Plan for PMK-234 (spec: docs/superpowers/specs/2026-11-09-pmk-234-prioritize-by-demand-guard-design.md).

1. Stale-write guard: step 6 of /pmkit:backlog:prioritize-by-demand keeps the `before` of each dry run. Step 8 re-runs those dry runs before the first write. If any `before` differs, or a dry run fails, it writes nothing, shows what changed and goes back to step 2 for a new ranking and a new confirmation. `issues bulk --expect` cannot be called here because bulk has no ID filter and applies one value to a set, so the command borrows its freeze-and-compare idea. No CLI change.
2. Ranking-only mode: a `rank-only` keyword argument stops the command after the ranking table. It proposes nothing, asks nothing and makes no write call.
3. Tests first: two new scenarios (stale preview, rank-only) and the re-check dry runs in the existing ones. Then the command file, goldens, CHANGELOG, README and SKILL.md. `npm test` must pass in the foreground before the PR.

Ceiling: `issues update` has no compare-and-set, so the window between the re-check and each write stays open.
