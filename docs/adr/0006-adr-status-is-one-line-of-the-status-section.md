# The status of an ADR is one line of its Status section

`docs adr-get` used to read the whole `## Status` section as the status (`Accepted Date: 2024-01-02`), so `docs adr-status` could only replace the whole section, and PMK-306 made it refuse when the section held anything else. MADR ADRs (`Accepted` plus a date line) and Nygard ADRs (`Accepted` plus `Supersedes ...`) could not be marked. The status is now one line, but only when it is a top-level paragraph line: the first non-blank line of the section after blank lines and one-line comments (`<!-- x -->`), not indented 4 columns, not a block opener (comment, quote, list item, fence, heading, table, HTML), not a link reference definition or thematic break, not a `Key: value` or `Supersedes` line, and it must read as a known status: with the emphasis and punctuation around it removed, its first word is `accepted`, `deprecated`, `superseded` (the `docs adr-status` values) or a common ADR status (`proposed`, `rejected`, `draft`), in any case. A date in any form (`**Date:** x`, `_Date:_ x`, `2024-01-02`) or a `**Supersedes**` line is therefore never the status, and an unknown status word leaves the section read whole and refused, as before PMK-311. `adr-get` reads that line alone and `adr-status` replaces that line in place, indent kept, and keeps every other line of the section. A section of one line reads and writes as before, whatever the line looks like (`- Accepted` alone included). A section of more than one line with no such line (a status inside a comment, fence, code, item or quote, after a date line, or a word that is not a known status) is read whole and a write is refused, exactly as before PMK-311, so nothing is rewritten inside a block and no date is taken for the status.

## Considered options

- One top-level paragraph line. Chosen. MADR and Nygard put the status first, as plain text; where the status is inside a block or after a date, replacing a line would write in the wrong place or delete text, so those sections stay refused.
- The first paragraph. Rejected: `Accepted` and `Date: 2024-01-02` on adjacent lines are one paragraph, so the date would still read as status.
- Keep refusing (PMK-306). Rejected: it leaves common formats unmarkable by `record-decision`.

## Consequences

- The reading contract changes: a status broken over two lines (`Superseded by` then `[ADR 5](0005-x.md)`, or `Accepted, with` then `conditions`) is read as its first line only, and a write replaces only that line. The line glued under it is kept, and a dry run says so in a note when it is a plain line (not `Key: value`) so the user can check that it is not the rest of the old status. `adrInfo` and `setAdrStatus` share `topLevelStatus`.
- A section of more than one line with no top-level status line is refused as "other text", as before PMK-311; its next step says to put the status on a plain line of its own at the top (other lines may follow it). The HTML block and code fence guards (PMK-299, PMK-302) are unchanged.
- `adr-status` writes no `Supersedes` line (the new ADR holds it), so `--by N` cannot duplicate one; a kept line that already names ADR N gets a note.
