# PMK-197: text redact trades false positives for no missed secrets

Follow-up of PMK-63 (`text redact`, PR #108). Files: `scripts/lib/redact.mjs`, `scripts/redact-probes.test.mjs`, `scripts/redact.test.mjs`, `scripts/__scenarios__/issues-investigate-bug.mjs`, and the text that lists the types (`commands/issues/investigate-bug.md`, `README.md`, CHANGELOG). Non-goals: the improvements in `docs/superpowers/epc-6-follow-ups.md`.

## Intent

`text redact` is a second layer over text the agent quotes. A leaked secret costs more than an over-redacted word, so the key/value rule changes from "redact when the value looks like a secret" to "redact unless the value is provably not one".

## The rule

A pair is `key` + a separator + value, where the key contains `password`, `passwd`, `pwd`, `credential(s)`, `secret`, `token`, `api_key` (or `apikey`), `private_key` or `authorization`, and the separator is `=`, `:`, `=>`, `:=`, `==` or `===`, with any space except a line break around it. The key starts with a letter, a digit, `_` or `.`, so the `-` of a removed diff line is not part of it, and it may have an index (`secret[0]=`, `token[value]=`) and close a quote, an escaped quote, a bracket or Markdown (a backtick, `*`, `**` or `~~`) before the separator (`{\"password\":`, `config["password"] =`, `headers['Authorization'] =`, `**password**:`, `` `DB_PASSWORD`: ``). A secret word in the index names the key too (`user[password]=`, `params[:password] =`, `data[api_key]=`); the index holds no `=`, so `login[password=Ab3]:xY9` is a pair inside a bracket. The value is replaced in full unless it falls under one of the exemptions below.

The rule has no per-character cases. After two review cycles in which each patch to a whitespace-delimited value opened a new gap (`|` inside a value, an opening backtick eaten, a YAML block under a diff `+`), the value now runs to the end of the line:

- **Quoted value:** the quoted text, with escaped quotes (and YAML's `''`) and line breaks inside, up to 4096 characters. A quote that never closes, or a closing quote followed by anything but a space, `,`, `;`, `)`, `]`, `}` or the end (`password="ab"cd`, `"abc"-def`, `'pa'"'"'ss'`), falls back to the line rule.
- **Any other value:** from the separator to the end of the line. In a table row (the line starts with `|`) it ends at the next `|`, so the other cells stay.
- **Markdown stays balanced:** only the Markdown that opened before the value and is still open there (a backtick, `**`, `__`, `~~`, `(`, `[`, `{`) keeps its last closing mark on the line that ends a word, that is a mark followed by sentence marks, quotes and closing marks up to a space or the end of the line (and `]` followed by `(`): `(token=x)`, `(token=x).`, `(token=x), then`, `` `token=x` first ``, `**token=x**!`, `[token: x](url)`. A closing mark inside the secret is not one: `login(password=Pa)ss!w0rd`, `login(password=Ab3)!xY9` and `connect(user=x, password=aB3)_kL9!,` lose all after the key, `__dirname token=abc__xyz` becomes `__dirname token=[redacted]`. A backtick, `**`, `__` or `~~` that closes a label right after the separator, with text after it, is the label's (`**Password:** hunter2` becomes `**Password:** [redacted]`, `` `password:` hunter2 `` becomes `` `password:` [redacted] ``). Markdown that opens inside the value (`` password: `hunter2` ``) goes with it.
- **Next line:** with nothing after the separator, a YAML `|` or `>` (with `+`, `-` or a digit, after an anchor or a tag, before a comment), only a comment (`password: # below`), or a value that opens `{`, `[` or `(` without closing it or ends in `\` (formatted JSON, HCL, a tuple, a shell line continuation), the value takes the lines below that are more indented than the key, blank lines and YAML comments (in any column) inside included. A lone opening mark stays with the closing line below it (`"credentials": {\n    [redacted]\n  }`). "More indented" is measured at the key's column, so a diff `+`, a log timestamp or a list `- ` before the key counts: a line belongs when it has a space at that column (and the same kind of character just before it), or more leading space, `+` and `-` than the key's line. With nothing after the separator and a `name:` pair (a colon then a space or the end of the line) as the first of those lines, they are a mapping: every value in it is replaced and the names stay (`secrets:\n  db: hunter2` becomes `secrets:\n  db: [redacted]`); a line in it with no `name:` goes whole. A `|` or `>` with no line below is left alone; a comment with no line below is the value (`PASSWORD=#hunter2`).
- **Authorization:** `"Authorization": "Basic ..."` (JSON) is redacted like the header line, after any space, with an escaped quote inside or no closing quote.
- **curl:** the value of `-u` (alone or after other short options, `-su`) or `--user` on a `curl` line is redacted when it holds a `:`. Type `curl_user`.
- **Order:** the private key, URL, Authorization and curl patterns run before the pairs, the token patterns (`jwt` to `bearer`) after them. A value after a secret key that starts with a token (`credentials: AKIA... wJalr...`, `token: ghp_... extra`) is one value, replaced to the end of the line and counted as `api_key_value`, so a mark at the start of a value can only come from an earlier pass.

## Exemptions (the only values left alone)

1. Already redacted: the mark, alone or followed by a space, `,`, `;`, a quote, a closing mark or the end of the text. Only an earlier pass can leave it there (see Order), so a second pass changes nothing and counts nothing. A mark followed by more of the value (`secret=[redacted]!Rest#9`) is replaced in full.
2. Empty, and an empty quoted value followed only by a separator, a closing mark or the end of the line (`{"password": "", "user": "bob"}`). `password: "" hunter2` falls back to the line rule.
3. A number that is the whole value after a key that names a quantity and does not end in the secret word: a plural (`max_tokens`, not the `ss` of `SECRET_PASS`) or a key ending in `limit`, `count`, `version`, `size`, `length`, `max` or `min` (`token_limit`, `secret_version`). With more after the number (`max_tokens=1000 hunter2`, `api_keys: 12345:abcdef`) the value goes. Any other key gets its number redacted: `token`, `GITHUB_TOKEN`, `CLIENT_SECRET`, `api_key`, `SECRET_KEY`, `SECRET_PASS`, `password1`, `password_confirmation`, `credentials.pin`, `token.value`.
4. A file location: a key ending in a source or config extension (`.ts`, `.py`, `.go`, `.c`, `.yaml`, `.txt` and the like), then `:` and `line`, `line:column` or `line-line`, then the end, a space, a quote, a backtick, a closing mark, a sentence mark, or a `:` or `.` before a space (`token.mjs:12:5`, `` `src/auth/password.ts:12` ``, `token.mjs:42-50`, `password.ts:12.`, `tests/test_password.py:42: AssertionError`). `config/password.txt:1:hunter2` (grep output) is not one and is redacted.
5. A key that is exactly `pwd` or `oldpwd` (the shell variable and the `pwd` command, not `DB_PWD`) with a value that starts with `/` or `~`: it is a directory. The scan goes on inside it, so `PWD=/home?token=...` still finds the token.

## False positives this accepts (the full list)

- The rest of the line after a secret key: `password: hunter2 and more`, `- token=x, then retry`, `a=1&api_key=x&b=2` (`&b=2` goes), `a=1,token=x,b=2`, and a second pair on the same line (`password=x and "password": "y"` is one mark).
- Prose after a key word: `token: expired`, `Unexpected token: < in JSON`, `the next token: a comma`, `csrf_token=abc in the form`, `Set the password: field in config.yaml` (the rest of the sentence goes).
- Code that names a key word: `password: string`, `const password = req.body.password`, `password: process.env.DB_PASSWORD`, `const token = getToken(req)`, `if (password === undefined) throw ...` becomes `if (password === [redacted])`.
- A name that holds a key word: `secretName: x`, `tokenizer=cl100k`, `tokens=lots`.
- Markdown: with a closing mark that opened before the value, the text up to its last occurrence on the line that ends a word goes, and a label in Markdown takes the rest of its line (`` The `password:` key is optional. `` becomes `` The `password:` [redacted] ``, `` - `password`: the database password `` becomes `` - `password`: [redacted] ``).
- The lines under a key with nothing after it, or with a value that opens a bracket, when they are more indented (`password = getPassword(\n  req\n)` loses `req`): `token:\n  see the docs`, `Error: invalid token:\n    at foo (src/a.js:1:2)` (the stack frame goes), `credentials:\n  - user: bob`, and every value of a mapping under a secret key (`secrets:\n  port: 5432`, `credentials:\n  username: admin`).
- `curl_user` matching `-u` of another command on a `curl` line: `curl x | sort -u -t: -k1` loses `-t:`.

## Ceilings kept (missed secrets that remain)

Recorded as follow-ups: `docker login -p`, `mysql -p...`, `wget --http-password x` and `--password x` (no `=` or `:`), `curl -u` on a continued line or after 500 characters.

- `pwd=/x9Kq` and `PWD=~/secret`: kept (exemption 5), a missed secret for a key named exactly `pwd`.
- A number that is the whole value after a key that names a quantity (`token_limit=482913`, `secrets=1234`), kept by exemption 3.
- The lines of a bracket opened after a secret key that are not more indented than the key (`password = (\n"hunter2"\n)`).
- A value on the next line at the indentation of the key (`password:\nhunter2`, not valid YAML) and a quoted value over 4096 characters that spans lines (its first line goes).
- A value the key does not name (`-p hunter2` in `docker login`, `Cookie: session=...`) stays; probes pin it.
- Not in the rule (review of PR #155, cycles 3 and 4, non-blockers): `Authorization` as an argument (`setRequestHeader('Authorization', 'Basic ...')`), a quoted value followed by more of it (`token = "ghp_" + "abc"`, `password = "x" if a else "y"`), a key with a space (`API Key: x`, `Secret access key: x`), Makefile `?=` and `+=`, `password != "x"`, the Kubernetes `- name: DB_PASSWORD\n  value: x` pair, `| password: | x |` across two cells, and `\|` inside a table cell (`| token=ab\|cd |` keeps `|cd`). Cycle 5: a literal over several lines (`password = """\nhunter2\n"""`, `secret = <<EOF`, `` token = ` ``) loses only its opening, a number after a file name in grep output (`secrets/api_token.txt:48291337`) stays under exemption 4, keys outside the issue's list (`MYSQL_PASS`, `SSH_PASSPHRASE`) pass, and a label in Markdown with its value on the next line (`**Password:**\n  hunter2`) stays.

## Tests

Every case in the issue has a probe with the output. Probes that pinned the old gaps now pin the new output; probes whose old output was an accepted false positive are changed with the list above as the reason. The scenario `expect` checks that no secret fragment of the draft survives (token, `hunter2`, the clone URL password) and that the Markdown around the quoted text stays.
