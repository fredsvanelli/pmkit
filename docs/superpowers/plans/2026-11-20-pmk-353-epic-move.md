# Epic move Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `pmkit epic move <id> <category> [--status <name>]` changes an epic's status on the Local, Linear and GitHub trackers, warns about open issues on a move to done or canceled, and `/pmkit:issues:move` accepts an epic ID.

**Architecture:** A new contract operation `moveDeliverable` that each adapter implements against its own epic status. `deliverableProgress` gains an `open` list of issue IDs. The CLI command `epic move` calls both and adds the warning. The command file `commands/issues/move.md` gets an epic path.

**Tech Stack:** Node 18+ ES modules, no dependencies (ADR 0003), `node:test`, ESLint through `npx`.

**Spec:** `docs/superpowers/specs/2026-11-20-pmk-353-epic-move-design.md` (approved). ADR 0011 holds the GitHub mapping.

## Global Constraints

- No dependency in `package.json` (ADR 0003). `npm test` and `npm run lint` pass after every task.
- Every commit message carries `(PMK-353)` and ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `moveDeliverable(id, category, actor, { status, dryRun = false } = {})` returns `{ before, after }` (epic records), on every tracker.
- Rules, in this order on every tracker: unknown epic → `NOT_FOUND`. Category not one of the seven → `INVALID_INPUT` (`category must be one of triage, backlog, todo, in_progress, in_review, done, canceled`). Category the tracker can't store for an epic → `INVALID_INPUT` `a <Local|Linear|GitHub> epic cannot move to <category>`, next step `Use one of: <categories>`. `--status` outside the category → `INVALID_INPUT` `status <name> is not in category <category>`, next step `Use one of: <names>`. No `--status` and the category equals the current one → `INVALID_INPUT` `epic <id> is already in <category>`. `--status` equal to the current status name → `INVALID_INPUT` `epic <id> is already in status <name>`.
- Default status: the category's first status (Local: `local.statuses` order; Linear: first by `position`; GitHub: the first row of the ADR 0011 table).
- A dry run makes no write and no remote mutation.
- The warning text is exactly `<id> still has open issues: <ID>, <ID>`, on a move to done or canceled, in the dry run and the real run. It never blocks.
- GitHub status update body is exactly `Status changed to <name>.`.

## Review Focus

- A lowercase or unpadded local ID (`epc-3`) moves the epic `EPC-3`, as `epic get` accepts it. Test in Task 1.
- A hand-edited `epic.md` with a comment or an extra key keeps them after a move: only the `status` line changes. Test in Task 1.
- An epic whose only non-done issues are canceled or archived gets no warning. Test in Task 4.
- A GitHub dry run from Closed to Complete sends no mutation at all. Test in Task 3.
- A GitHub reopen that succeeds while the update fails answers `UPSTREAM` naming the Project, and the Project reads as open afterwards. Test in Task 3.
