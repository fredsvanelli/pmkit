# Changelog

## Unreleased

- Warns when the `## Status` section of an ADR is empty because a setext underline makes its first line a heading (PMK-294). `docs adr-get` and `docs adr-status` add a note, in the JSON and the text, that names the line (`Accepted` over `---` or `===`) and says to remove the underline so it reads as the status, and return `statusHeading` (the line, or `null`). The note comes from `sectionEnd`, so a list item, a quote or a thematic break over `---` gets none. What is read and written is unchanged; the PMK-283 test now covers `===` too.
- Fixes the title that `docs adr-get` shows for an ADR whose `# ` heading has a closing `#` sequence (PMK-293). `# 5. Use X #` gave `5. Use X #` and now gives `5. Use X`, because the title is read with the same helper as the `## Status` heading: a run of `#` after a space or tab closes it, and `\#` or a `#` glued to the word does not. As in CommonMark, only the last run closes the heading, so `# 5. Use X # #` gives `5. Use X #` and `## Status # #` is not the Status section (the acceptance criterion of PMK-293 said it was, and was corrected). Tests pin `## Status #`, `## Status # #` and `## Status \#`.
- Tests only: pins the CommonMark end of the `## Status` section for an empty list item (`-`, `*`, `1.`) followed by a line and a `===` or `---` underline, for a 10-digit ordered marker, and for the 9-digit limit, in `adrInfo`, `setAdrStatus`, `docs adr-get` and `docs adr-status` (PMK-292). The behaviour is already in place from PMK-291; `scripts/lib/adr.mjs` is unchanged.
- Makes `hideAbsolutePaths` take time linear in the line (PMK-288). A line of 200,000 characters of `a.`, `a+` or `a-` took 34 seconds, `a+` repeated before `file` 100 seconds, and a line of quotes or backticks that open a path and never close 28 seconds; each now takes under 15 ms. The output is the same: the URL rule starts only at the start of a run of scheme characters and puts back the text before its first letter, and the quoted-path rule looks for the closing quote by hand and remembers a failed search for the rest of the line.
- Redacts the user name of an `http` or `https` URL in `hideAbsolutePaths` (PMK-287). `unable to access 'https://bob@host/r.git/': 403` now shows `https://[redacted]@host/r.git/`, like a URL with a password or a token already did. `git+https://bob@host` follows the same rule, and the user runs to the last `@` before the path, a `?` or a `#`. `ssh://git@host`, `git+ssh://git@host`, `git@host:path`, a URL with no user and `<remote>/<branch>` are unchanged, and the rules of `redact.mjs` for other text are too.
- Fixes `hideAbsolutePaths` for a `<scheme>+file://` URL (PMK-286). `git+file://host/Users/a/r.git` and `git+file:///Users/a/r.git` now hide the path like `file://` does (`git+file:<path>`), quoted ones end at the closing quote (`'git+file:///Users/a/r': cause` shows `'git+file:<path>': cause`), and an unquoted one runs to the end of the line. `git+ssh://` and `git+https://` stay whole URLs with the credentials redacted. The `file:` pieces of the quoted rule and of the URL exclusion are one constant, `FILE_SCHEME`.
- Fixes `hideAbsolutePaths` for a quoted `file://` URL (PMK-285). `fatal: 'file:///Users/a/r': does not appear to be a git repository` now shows `fatal: 'file:<path>': does not appear to be a git repository` instead of cutting the line after `file:<path>`: the URL ends at its closing quote, with the same closing rule as a quoted path. An unquoted `file://` URL still runs to the end of the line.
- Hides the absolute paths left in git and gh error texts (PMK-289). The stderr of a failed `gh` call goes through the same hiding as git's, and an HTTP status is still read from the raw line first, so `gh api` errors keep `httpStatus`. `link-repo` no longer names the project root when it is not the git root, `todos scan` says `cannot list the files of this repository`, and the spawn error messages of the tag check and the mention scan are hidden too.
- Fixes `hideAbsolutePaths`, used by the `UPSTREAM` message of a failed `auto_commit` and the other messages that repeat git's text (PMK-284). An absolute path right after a backtick, `{`, `|` or `>` (`` `/Users/x` ``, `{/Users/x}`, `a|/Users/x`, `2>/Users/x`) is now hidden like one after a space or a quote. A backtick quotes like `'` and `"`, so `` x `/Users/a/r` y `` shows as `` x `<path>` y ``. A quote that closes before `]` or `>` now closes the quoted path, so the text after it shows: `'/Users/a/r'] gone` is `'<path>'] gone`, where it used to lose `] gone`. The expectation of the PMK-277 test `['/Users/x y'] and '/b c/d'` changes from `['<path>'` to `['<path>'] and '<path>'` for that reason; the O'Brien cases (PMK-271) and the URL rules (PMK-278) are unchanged. A `>` starts a path only as a redirect (after a line start, a space, a digit, `&` or another `>`: `2>/x`, `&>/x`, `>>/x`), so `usage: git push <remote>/<branch>` is unchanged; a digit counts only when it is not the end of a word or a revision (`<rev1>/<rev2>`, `HEAD~1>/x` are unchanged). A backtick opens a path only when it is itself at a start, so the closing backtick of `` `git`/`gh` `` opens nothing. A quote closes before `]` or `>` only when those are followed by the end of the line, a space, `:` or `)`, so `'/Users/x/a'>b/secret dir/y' tail` is hidden up to the end of the quoted path. The negative lookbehind the review suggested is not used: the start characters are one explicit constant.
- Fixes `issues branch` in a clone or worktree where the default branch exists only on the remote (PMK-290). Without `--from`, it starts from the local default branch when there is one, and otherwise from `origin/<default>`, the remote `pr open` pushes to; the text says `(no local <default>)` and `from` in the JSON is the ref used, `origin/develop`. Nothing is fetched. A `--from` that is not a branch or commit, or a default branch that is neither local nor on `origin`, now fails with `INVALID_INPUT` and a next step (`git fetch origin` or `--from`) before anything is written, in `--dry-run` too, instead of git's `invalid reference`. The real run now returns `from` in its JSON like the dry run.
- Fixes where `docs adr-get` and `docs adr-status` end a `## Status` section that holds lists, quotes or code (PMK-291). The end is now the first heading at the top level of the document, found by a walk that follows CommonMark's block structure (open quotes and list items with the content column of each, a line continuing the deepest one it reaches, indented code only 4 columns past the content of the block that holds it, lazy lines, fences) instead of looking back from each underline. A wider sibling item (`- x\n\n1. a\n\n  b\n---`), a fence at column 0, a fence right after a closing fence, an empty item (`- a\n-\n\n  x\n---`) and a marker with 5 or more spaces (`-     a\nlazy\n\n  x\n---`) end the list, so `x` or `b` is a heading; a lazy line (`- a\nlazy\n\n  b\n---`), an item nested 4 columns in (`- a\n    - m\n\n      c\nlazy\n---`) and a quote inside an item keep the line inside the item, so `---` is a thematic break; indented code inside an item (`- a\n\n      x\nlazy\n---`) does not continue it. An HTML block (the seven CommonMark kinds, with their ends; kind 7, a custom tag alone on its line, does not interrupt a paragraph) and a paragraph of link reference definitions only are not setext headings, so `-\n<!-- x -->\n---` and `-\n[a]: /u\n---` keep the whole section, and a fence inside an HTML comment no longer runs the section to the end of the file. The link title pattern reads an escape in one step, so an unclosed title full of `\!` no longer takes time that doubles with each escape. A heading inside a list item or a quote no longer ends the section, and `Accepted\n\n-\nfoo\n===` now ends it at `foo`, as CommonMark does (the PMK-281 test expected the list to hold `foo`). `scripts/dev/adr-commonmark-diff.mjs` compares `adrInfo` of two refs with commonmark.js installed outside the repository; it is not part of `npm test`.
- Pins with tests what `docs adr-get` and `docs adr-status` do on a `## Status` section whose text is underlined by `---` (PMK-283). `## Status\nAccepted\n---` reads as a setext heading, as CommonMark does, so the section is empty and `adr-status` writes `Deprecated` above the `Accepted` heading. A human reader then sees two status-like entries; the tests fix this current behaviour and change no code.
- Fixes `docs adr-get` and `docs adr-status` on an ADR whose `## Status` heading is indented by one to three spaces or has a closing `#` sequence (PMK-282). ` ## Status`, `##<tab>Status`, `## Status ##` and `## Status #####` used to be missed, so the ADR read as having no status and `adr-status` added a second `Status:` line. The heading is now found with the same ATX rule as the title and the end of the section, and `adr-status` rewrites the body and keeps the heading as written. `## Status#`, four spaces, a fenced heading and a setext `Status` are still not the section.
- Fixes `docs adr-get` and `docs adr-status` on an ADR whose `## Status` section has a line that CommonMark does not let interrupt a paragraph above a setext underline (PMK-281). `2. foo` (an ordered item interrupts a paragraph only when it starts at 1) and an empty item (`-`, `*`, `1.`) are now part of the paragraph, so `Accepted\n2. foo\n===` is a setext heading and the section ends at `Accepted`; after a blank line they still start a list and the section stays open. A line indented by four columns (a tab counts up to the next stop of 4) after a blank line is indented code, not the start of the paragraph: `Accepted\n\n\tcode\nmore\n===` ends the section at `more`, and inside a paragraph a tab line is a continuation. `- - -` and `* * *` are thematic breaks, not list items, when a line is checked for belonging to an item (PMK-280). Still one parser for both commands.
- Fixes the `UPSTREAM` message of a failed `auto_commit` (PMK-277). An absolute path right after `[`, `,`, `;`, `<` or `@` (`[/Users/x/repo]`, `a,/Users/x`, `a;/Users/x`, `</Users/x>`, `user@/Users/x`) is now hidden like one after a space, `(`, `=`, `:` or a quote. A `]` or `>` after the path goes with it, so no part of the path shows.
- Fixes `docs adr-get` and `docs adr-status` on an ADR whose `## Status` section has an indented list item continuation right above a `---` (PMK-280). `## Status\n\nAccepted\n\n- a\n\n  b\n---` used to end the section at `b`, taking it for a setext paragraph, so `adr-get` lost `b` and `---` and `adr-status` left them under the new status. A line indented to the content of a list item above it (blank lines between them allowed) now belongs to that item, and the `---` is a thematic break, as CommonMark says, so the section stays open. A line indented less than the item content, or not indented, is still a setext paragraph. This is not a full list parser: the nearest item that fits decides.
- Fixes step 2 of `/pmkit:spec:record-decision` (PMK-274). It keeps only the older ADR's `number` and no longer tells the agent to keep its `ref` for the `Supersedes:` line, which cites `supersedesRef` as step 4 says. `ref` is described as the path the user sees, and the `../...` form is no longer explained there.
- Fixes the other messages that repeat git's own error text (PMK-278). `hideAbsolutePaths`, which PMK-271 used only for a failed `auto_commit`, now also hides the absolute paths in git's text in six more places: the `git grep` failure listed as `unchecked` by `issues delete`, the `cannot check tag` warning, the git remotes reason of `link-repo`, the file listing error of `todos scan`, the `git for-each-ref` note of `inbox mark-read`, and the `UPSTREAM` message of a failed `git` call of `pr open` (push, switch, branch, diff). Only git's text is hidden: a folder the user passed and the command repeats (`cannot list the files of <root>`) is unchanged, a `gh` message is unchanged, and the `auto_commit` message is exactly as PMK-271 made it. `hideAbsolutePaths` now leaves a URL `scheme://host/...` (`https`, `http`, `ssh`, `git`) whole, so `fatal: unable to access 'https://github.com/o/r.git/': The requested URL returned error: 403` keeps its cause; it used to show `https:<path>`. The credentials of such a URL are replaced by `[redacted]` (`https://user:pw@host/...` shows `https://[redacted]@host/...`, and a bare token such as `https://ghp_...@host/...` is redacted too, by the patterns of `redact.mjs`). A `file://` URL, with or without a host (`file://localhost/Users/John Doe/r.git`), a path without a scheme and a UNC path `\\host\share` are still hidden. The rule serves every caller, `auto_commit` included.
- Fixes the `UPSTREAM` message of a failed `auto_commit` (PMK-271). An absolute path with a space no longer shows part of itself (`/Users/John Doe/.gitconfig` used to leave `Doe/.gitconfig`), and a Windows UNC path (`\\host\share\...`) is hidden too. A path inside quotes is hidden up to the closing quote, and one outside quotes up to the end of the line, so the message can lose text after a path but never shows part of one. With more than 5 files outside the repository, the next step now names the tracker folder from `tracker.path` (`Commit the tracker files in ../tracker ...`); an absolute `tracker.path` is still never shown.
- Fixes `docs adr-get` and `docs adr-status` on an ADR whose `## Status` section is followed by a heading that PMK-269 did not recognise (PMK-273). The section now ends at every CommonMark heading form outside a fenced code block: a setext heading (text underlined with `===` or `---`, the whole paragraph above the underline), an ATX heading indented by up to three spaces, with a tab after the `#`, or empty (`##` alone). `adr-get` shows only the status text and `adr-status` keeps those headings and the text under them. A `---` after a blank line is a thematic break and does not end the section. A line of text directly above a `---` or `===` with no blank line between them is now a setext heading, as CommonMark says, so `## Status\nAccepted\n---` ends the section at `Accepted`; a quote, a list item or a thematic break above the underline interrupts the paragraph and the section stays open. `## Context` indented by up to three spaces, and a `# ` title indented the same way, are found by the same heading test. Both commands still share one parser.
- Fixes the `Supersedes:` line that `/pmkit:spec:record-decision` writes with both ADRs in a tracker outside the repository (PMK-270). `docs adr-get` takes `--from <path of the new ADR>` and returns `supersedesRef`, the old ADR's path relative to the folder of the new one (`Supersedes: ADR 0001, 0001-a.md`), the same base `docs adr-status --by` writes into the old ADR; ADRs inside the repository, a tracker inside it and a new ADR in the repository keep the path from the repository root, and `ref` is unchanged. The base rule is one helper, `adrRef`, shared by both commands. Step 4 of the command file reads it once the new path is known, and step 5 reads it again when the number or the path changes.
- Adds tests that pin the one-second unarchive history limit of PMK-267 (PMK-272). Four real archive and unarchive calls in one second show two events in `issues get --history` and leave the issue active, which is the known ceiling of the merge rule and not a merge copy; `issues bulk unarchive --limit` on the Local tracker answers `INVALID_INPUT` with the flag's usage message. No behaviour change.
- Fixes `docs adr-get` and `docs adr-status` on an ADR whose `## Status` section has a subsection (PMK-269). The section now ends at the first heading of any level outside a fenced code block, not only at `#` or `##`, so `adr-get` shows just the status text and `adr-status` rewrites only that text and keeps a `### Notes` subsection and everything after it.
- Fixes `docs adr-status` and `auto_commit` with a tracker folder outside the repository (PMK-268). A failed auto_commit no longer shows an absolute path in the `UPSTREAM` message: git's own text has the repository folder removed (and any other absolute path replaced by `<path>`), and the next step names the files relative to the tracker's git repository. `superseded --by` with both ADRs in that tracker writes the newer ADR's path relative to the ADR that holds the line (`Status: superseded by 0003-x.md`), so a reader of the tracker alone can follow it; an ADR that names a repository ADR, and every other pair, keeps the path from the repository root, and `path` and `ref` in the JSON are unchanged. `climbsOut` (now in `scripts/lib/paths.mjs`) sees a path that leaves its base with `/` or `\` and a Windows absolute path on any system. `issues update`, `issues assign` and `issues create` have tests that commit into such a tracker.
- Fixes two cases PMK-256 left over (PMK-267). A git merge that repeats an archive, unarchive, archive, unarchive run made within one second now shows each event once in the issue history, and `issues bulk unarchive` on Linear answers `NOT_SUPPORTED` whatever flags it gets, instead of the unknown-flag error for a flag like `--limit`.
- Improves the ADR commands (PMK-263). `docs adr-get <number>` reads one ADR (number, title, status, path, ref and place) and writes nothing, and `/pmkit:spec:record-decision` uses it instead of the `docs adr-status --dry-run` call. A decision may replace several ADRs: the new ADR gets one `Supersedes:` line per ADR and the older ADRs are marked together after one confirmation, and a failure in the middle lists the ADRs marked and the ones left. The command warns when a replaced ADR is newer than the new one, does not ask again for ADRs the user named, and mentions a failure of step 6 before asking to mark the older ADRs. `docs adr-status` also changes a `Status:` or `**Status:**` line above the first section when the ADR has a `status:` key or a `## Status` section, and reports every place it changed. `validate` already reports a number used twice in `docs/adr/` with a hosted tracker (PMK-228).
- Fixes four edge cases of `unarchive` (PMK-256). A git merge that repeats a whole archive, unarchive, archive, unarchive run no longer doubles the events in the issue history: a repeated archive or unarchive event is kept only when it follows an event of the same second, as before. `issues bulk unarchive --view` with a view that lacks `archived` says to save the view with `--archived` (`views save <name> ... --archived --overwrite`) instead of "Add --archived to the filter". On Linear, `issues bulk unarchive` answers `NOT_SUPPORTED` before any other check, so `--view` no longer gets the hosted-view error first, and the refusal is built in one place (`unarchiveNotSupported`). A bulk unarchive counts only archived issues against `--max` and `hasMore`; a test now locks it in.
- Fixes `docs adr-status` (PMK-257). With a tracker folder outside the repository and `auto_commit: true`, the write is committed in the git repository that holds the tracker folder, as every Local write is; before, git was given a path outside the project and the command failed with `UPSTREAM` and an absolute path. A tracker folder in no git repository is written without a commit and a `note:` says so. `superseded --by` to an ADR in such a tracker writes its path from the repository root (`../trackers/x/docs/adr/0003-x.md`, also the `ref` in the JSON) instead of `docs/adr/<name>`, which did not exist in the repository; `path` keeps the `tracker:` label. An unchanged status reports the same text before and after, an ADR with the status in both its front matter and its `## Status` section reports both (`status: accepted; ## Status: Accepted`), and `status: accepted # comment` counts as accepted and keeps its comment.
- Improves `/pmkit:spec:record-decision` (PMK-251). It asks whether the decision replaces an older ADR. When it does, the new ADR gets a `Supersedes: ADR <number>, <path>` line under its title, and after the ADR is written the command marks the older ADR superseded with `docs adr-status ... --by`, after its own confirmation; a decline or a failure leaves the older ADR untouched and offers `/pmkit:spec:adr-status`. A decision that replaces no ADR is written as before. `docs adr-status` also returns `ref`, the ADR path without the `tracker:` display label, in its JSON and dry run, and the Supersedes line uses it.
- Adds issue docs on Linear (PMK-252). `issues get` lists the docs of a Linear issue and `issues update --add-doc` and `--remove-doc` write them, as links (attachments) to the file on GitHub, `https://github.com/<git_host.repo>/blob/<default branch>/<path>`, with the path kept in the attachment's metadata so other attachments never read as docs. Adding needs `git_host.system: github` with a `repo` (`NOT_CONFIGURED` otherwise, before any write); `--dry-run` sends no write. The docs of up to 100 issues are read in one request, and a read Linear refuses shows the docs as `unknown` with a `note:`, never as none, and refuses a docs write. The manifest no longer lists `issueDocs` as unsupported, and `/pmkit:spec:record-decision` links the ADR on Linear too. The link uses the default branch as `default-branch` resolves it (origin/HEAD when `git_host.default_branch` is unset, with its note). A path that is absolute, a `tracker:` label or has `..` is refused (`INVALID_INPUT`) before any request, and `./docs/a.md` is `docs/a.md`. An attachment a person made with the same link is never taken over or removed (`CONFLICT`). The migration's doc links loss says the docs are not carried over. The checks still owed against the live API are in `API-VERIFICATION.md`.
- Adds Linear releases (PMK-246). On a workspace with releases on, `release list` and `release get` read Linear releases: the releases of the pipelines linked to the scope team, with the release UUID as the id, `released` from `completedAt`, and canceled releases left out (`release get` of one is `NOT_FOUND`). `issues get`, `issues list`, saved views and the result of every issue write show an issue's `release`, or `releases` (a Linear-only list) when it is in two or more; a list reads them in one request per 100 issues. A release of a pipeline that is not linked to the scope team is refused with `INVALID_INPUT`, as a milestone of another project is. `issues update --release <id|none>` and `issues bulk release` swap the issue's one release (`addedReleaseIds`, `removedReleaseIds`) and refuse an issue in two or more releases with `INVALID_INPUT` (the same words on every issue, so a bulk change shows them on each). The scope grew by decision PMK-246-2: the `release` filter of `searchIssues` and `release issues` now work on Linear, so `release-readiness` and `release-notes` by release no longer break once `release list` answers; `issues list` still has no `--release` flag (PMK-146). `release-notes` now says when the tracker cut its read (`truncated: true`, a warning and an `incomplete:` line), on Linear and Local alike, and `complete` is false when the read was cut or `problems` is not empty. When Linear refuses or fails the read of an issue's releases, the issue still comes back with `releaseUnknown` (the reason; the text says `release: unknown`) and a `note:`, never as "no release", and `issues update --release` refuses. The release queries keep small selections and pages to stay under Linear's complexity limit. With releases off the reads keep their empty answer and note, and the writes and the filter refuse with `Linear releases are off in this workspace`. `issues create --release`, `release create` and `release mark-released` stay `NOT_SUPPORTED`, and the manifest lists the last two in `releases.detail.unsupported`. The mapping follows Linear's public schema and runs against the fake; `scripts/lib/linear/API-VERIFICATION.md` lists what a real workspace with releases still has to confirm, so criterion 5 stays open.
- Improves the ADR folders (PMK-247). With `tracker.path: .`, `docs adr-status` writes the ADR through the tracker, so `auto_commit` commits it, and `docs next-adr` answers `destination: tracker` with a `docPath`, as for any other tracker path; before, the shared folder counted as the repository's and nothing was committed. A tracker at `tracker.path: .` with ADRs already in `docs/adr` now commits them through `auto_commit` on the next `adr-status`.

New changes `due <YYYY-MM-DD|none>`, `type <type|none>` and `archive` (no value; the preview warns that archived issues leave every list and are never matched by a bulk change again), through `updateIssue` and `archive` on both trackers, with the same preview, digest and stop midway.
